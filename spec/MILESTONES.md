>    - את תוצאות הבדיקה של כל סעיף ב-Definition of Done: עבר, לא עבר, והסבר קצר.

> 5. אין להוסיף פיצ'רים, מסכים או התנהגויות שאינם מופיעים ב-PRD, ב-ARCHITECTURE או ב-DESIGN.

## Milestone 1 – הקמת הפרויקט ופריסה אוטומטית ✅

> **הערה (אושר בהחרגה):** Milestone 1 אושר על בסיס ההרצה המקומית. העלאה ל-GitHub, חיבור Vercel והגדרת משתני הסביבה שם נדחו לשלב מאוחר יותר, ויבוצעו לפני הבדיקה בטלפון / בכתובת Production. Spend Limit של 10$ הוגדר בפרויקט הפיתוח ב-OpenAI.

**שם ומטרה:**
הקמת שלד הפרויקט ומסלול פריסה אוטומטי מ-GitHub ל-Vercel, כך שכל שינוי בהמשך ייבדק בכתובת Preview אמיתית.

**מה יש לממש:**
- פרויקט Next.js 16 ‏(App Router, TypeScript, Tailwind CSS), עם מבנה התיקיות שמוגדר ב-ARCHITECTURE.md.
- `layout.tsx` עם `lang="he"` ו-`dir="rtl"`, ודף ראשי זמני שמציג את הכותרת "חה חה חה".
- `.gitignore` שחוסם את קובצי ה-`.env`, וקובץ `.env.example` עם `OPENAI_API_KEY` ו-`OPENAI_MODEL`, בלי ערכים אמיתיים. ממנו נוצר קובץ `.env` מקומי, שאת ערכיו המשתמשת ממלאת בעצמה.
- **פעולות של המשתמשת, בהדרכה צעד אחר צעד:**
  - התקנת Node.js (גרסת LTS) במחשב, לצורך ההרצה המקומית.
  - יצירת Repository ב-GitHub ודחיפת הקוד אליו.
  - יצירת חשבון Vercel (תוכנית Hobby) וחיבור הפרויקט ל-Repository.
  - יצירת שני Projects ב-OpenAI, אחד לפיתוח ואחד ל-Production, והפקת מפתח API לכל אחד מהם.
  - הגדרת Hard Spend Limit של 10$ בחודש בכל אחד משני ה-Projects ב-OpenAI.
  - מילוי מפתח הפיתוח בקובץ `.env` המקומי.
  - הגדרת משתני הסביבה ב-Vercel:
    - `OPENAI_API_KEY` כ-Sensitive: מפתח הפיתוח בהיקף Preview, ומפתח ה-Production בהיקף Production.
    - `OPENAI_MODEL=gpt-5` בשני ההיקפים.

**תוצר מצופה:**
דף עברי פשוט שרץ במחשב המקומי וזמין גם בכתובת Production, ו-Preview Deployment שנוצר אוטומטית לכל ענף.

**Definition of Done:**
- [ ] האתר רץ במחשב המקומי (`npm run dev`) ונפתח בדפדפן.
- [ ] הקוד נמצא ב-Repository ב-GitHub, וקובץ `.env` אינו קיים בו.
- [ ] Push ל-`main` יוצר פריסת Production אוטומטית שעוברת בהצלחה.
- [ ] Push לענף אחר יוצר Preview Deployment עם כתובת זמינה.
- [ ] הדף מוצג בעברית, בכיוון RTL, בדפדפן במובייל.
- [ ] משתני הסביבה מוגדרים ב-Vercel להיקפים הנכונים, והמפתחות מסומנים Sensitive.
- [ ] בשני ה-Projects ב-OpenAI מוגדר Spend Limit של 10$ בחודש.

## Milestone 2 – קבלת בדיחה מקצה לקצה

**שם ומטרה:**
מימוש היכולת המרכזית של המוצר: המשתמש מזין נושא, או משאיר את התיבה ריקה, ומקבל בדיחה בעברית במסך המעוצב.
מכסה את User Stories 1–4 ו-6, ואת Flows 1–3 ב-PRD.

**מה יש לממש:**
- **Backend:**
  - `POST /api/joke`, לפי חוזה ה-API ב-ARCHITECTURE.md.
  - ולידציה בשרת: מחרוזת, `trim`, ועד 100 תווים.
  - `joke-service` (server-only), שקורא ל-OpenAI Responses API עם המודל שמוגדר ב-`OPENAI_MODEL`, עם ההנחיות הקבועות ועם הנושא כתוכן משתמש נפרד.
  - `maxDuration = 30` ו-Timeout של כ-25 שניות.
- **Frontend – המסך הראשי, לפי DESIGN.md:**
  - האיור הראשי, הכותרת, תיבת הטקסט (`maxLength=100`), הלחצן ובועת הבדיחה.
  - הגופנים Secular One ו-Rubik, ה-Color Palette, קווי המתאר, הצללים הקשיחים ורקע ה-Halftone.
  - מצבי המסך: ברירת מחדל (בועת בדיחה ריקה), Focus, טעינה (Pill "חושב על בדיחה..." במקום הבועה, ולחצן Disabled) והצגת בדיחה. בקשה חדשה מחליפה את הבדיחה הקודמת.
  - רוחב מקסימלי של 480px, ממורכז, במסכים רחבים.
  - האיור הראשי: העתקת `spec/image.png` ל-`public/hero.png`.
  - כל טקסטי הממשק מרוכזים ב-`lib/ui-text.ts`.

**תוצר מצופה:**
בהרצה המקומית אפשר להזין נושא, ללחוץ ולקבל בדיחה בעברית במסך שתואם ל-Mockups.

**Definition of Done:**
- [ ] נושא בעברית, למשל "חתול", מחזיר בדיחה בעברית על הנושא.
- [ ] תיבה ריקה, או תיבה עם רווחים בלבד, מחזירה בדיחה כלשהי בעברית.
- [ ] נושא באנגלית מחזיר בדיחה בעברית.
- [ ] אי אפשר להקליד יותר מ-100 תווים. בקשה ישירה לשרת עם יותר מ-100 תווים מחזירה `400`.
- [ ] בזמן טעינה מוצג חיווי הטעינה, הלחצן מושבת, ולחיצות חוזרות אינן שולחות בקשה נוספת.
- [ ] בקשה נוספת מחליפה את הבדיחה הקודמת.
- [ ] המפתח לא מופיע בקוד צד הלקוח ולא בתעבורת הרשת של הדפדפן. בודקים בחיפוש ב-Bundle וב-DevTools.
- [ ] המסך תואם ל-Mockups ול-DESIGN.md: צבעים, גופנים, פינות, קווי מתאר, צללים ו-RTL. נבדק בתצוגת מובייל בדפדפן, ובטלפון אחרי העלאה ל-Production.
- [ ] במסך מחשב, אזור התוכן אינו רחב מ-480px והוא ממורכז.

## Milestone 3 – טיפול בשגיאות ובחיבור

**שם ומטרה:**
הצגת הודעות ברורות כשאין חיבור לאינטרנט או כשמשהו נכשל.
מכסה את User Story 7, ואת שורות השגיאה בטבלת מקרי הקצה ב-PRD.

**מה יש לממש:**
- **שרת:**
  - מיפוי שגיאות OpenAI ו-Timeout לתשובת `502` (`generation_failed`).
  - סירוב של המודל (`NO_JOKE`) או פלט ריק מוחזרים כתשובת `422` (`no_joke`).
  - בלוג נרשמים רק סוג השגיאה וקוד הסטטוס, בלי תוכן הנושא או הבדיחה.
- **לקוח:**
  - זיהוי מצב Offline: `navigator.onLine` או כישלון רשת ב-`fetch`.
  - הודעת Alert – Offline: "אין חיבור לאינטרנט. נסו שוב כשהחיבור יחזור."
  - הודעת Alert – Error כשהמודל לא החזיר בדיחה (`no_joke`): "אופס, משהו התפקשש - נסו שוב".
  - הודעת Alert – Error לכל שגיאה אחרת: "משהו השתבש. נסו שוב."
  - עיצוב ההודעות לפי DESIGN.md, במיקום אזור הבדיחה.
  - אחרי שגיאה הלחצן חוזר להיות פעיל, ואפשר לנסות שוב.

**תוצר מצופה:**
בכל תקלה המשתמש רואה הודעה מתאימה בעברית, ויכול לנסות שוב.

**Definition of Done:**
- [ ] ניתוק הרשת אחרי שהדף נטען, ואז לחיצה על הלחצן, מציגים את הודעת ה-Offline.
- [ ] כשהשרת מחזיר שגיאה (מדמים מפתח שגוי או מודל לא קיים בהרצה המקומית), מוצגת ההודעה הכללית.
- [ ] כשהמודל מסרב לכתוב בדיחה, מוצגת ההודעה "אופס, משהו התפקשש - נסו שוב", וטקסט הסירוב של המודל אינו מוצג.
- [ ] אחרי שגיאה, לחיצה חוזרת עם חיבור תקין מחזירה בדיחה.
- [ ] בלוגים של השרת (בהרצה המקומית וב-Vercel) לא מופיע תוכן הנושא או הבדיחה.
- [ ] ההודעות מעוצבות לפי DESIGN.md.
- [ ] כל הסעיפים ב-Definition of Done של Milestone 2 עדיין עוברים.

## Milestone 4 – התקנה כ-PWA ופתיחה בלי חיבור

**שם ומטרה:**
מאפשרים להתקין את האתר כאפליקציה ולפתוח אותו גם בלי חיבור.
מכסה את User Story 5, ואת Flows 4–5 ב-PRD.

**מה יש לממש:**
- `app/manifest.ts`, לפי ARCHITECTURE.md: השם "חה חה חה", ‏`lang="he"`, ‏`dir="rtl"`, ‏`display: standalone`, ‏`theme_color` ב-Comic Yellow ו-`background_color` ב-Cream.
- אייקוני PWA בגדלים 192px, ‏512px ו-maskable: אימוג'י צוחק על רקע Comic Yellow, לפי DESIGN.md.
- `public/sw.js`:
  - שמירה מראש ב-Cache של מעטפת האפליקציה, כולל האיור. הגופנים אינם נשמרים ב-Cache.
  - Network-only עבור `/api/*`.
  - ניקוי Caches ישנים לפי גרסה.
  - רישום ה-Service Worker ב-Production בלבד.

**תוצר מצופה:**
אפשר להתקין את האפליקציה במסך הבית בשם "חה חה חה". היא נפתחת כמו אפליקציה, ונטענת גם בלי חיבור.

**Definition of Done:**
- [ ] הדפדפן במובייל מאפשר להתקין את האתר, והאייקון מופיע במסך הבית בשם "חה חה חה".
- [ ] האפליקציה המותקנת נפתחת במצב standalone, בלי שורת כתובת.
- [ ] במצב טיסה, האפליקציה המותקנת נטענת עם הצבעים, הפריסה והאיור (הגופנים מוחלפים בגופן מערכת), ולחיצה על הלחצן מציגה את הודעת ה-Offline.
- [ ] תשובות `/api/joke` אינן נשמרות ב-Cache. בודקים ב-DevTools, ב-Application → Cache Storage.
- [ ] בדיקת Lighthouse מאשרת שהאתר Installable.
- [ ] כל הסעיפים ב-Definition of Done של Milestones 2–3 עדיין עוברים.
